# Требования к API для лабораторной работы

Источник исходного поведения — репозиторий ealeksbykova/garage, commit 92a9cdadd73fc96eecbd40f38393a8d6163b6e5e.
В репозитории нет отдельной спецификации требований. Ниже зафиксирован учебный контракт;
ограничения валидации и критерии производительности добавлены в рамках лабораторной работы,
а не представлены как опубликованные требования автора проекта.

## Контракт

- Пять ресурсов: /api/engines, /api/transmissions, /api/on-board-computers, /api/wheels, /api/vehicles.
- POST коллекции: 201 и созданный JSON с положительным id.
- GET коллекции или существующего id: 200 и JSON.
- PUT существующего id: 200 и обновлённый JSON; изменения фиксируются до ответа.
- DELETE существующего id: 204 без тела.
- Отсутствующий объект или указанный компонент: 404.
- Нарушение входных ограничений / некорректный JSON: 400.
- Конфликт уникального VIN, serialNumber или назначения компонента: 409.
- Данные с ошибкой валидации не записываются. Ошибка связи откатывает всю транзакцию.
- Даты новых объектов и данные V2 должны читаться после сохранения.
- Двигатель, трансмиссия, компьютер и колесо принадлежат не более чем одному автомобилю.
- Удаление компонента обнуляет ссылку; удаление автомобиля удаляет join, сохраняя компоненты.

## Поля

- Engine: engineType из PETROL/DIESEL/ELECTRIC/HYBRID; horsepower > 0; serialNumber непустой до 64 знаков. Необязательные volumeLiters и torqueNm >= 0.
- Transmission: transmissionType из MANUAL/AUTOMATIC/CVT/ROBOTIC; gearsCount >= 0 (0 допустим у CVT); serialNumber непустой до 64 знаков.
- Computer: firmwareVersion непустая до 50 знаков; cpuModel до 100 знаков; необязательная ramMb >= 0.
- Wheel: position из FRONT_LEFT/FRONT_RIGHT/REAR_LEFT/REAR_RIGHT; radiusInch > 0; serialNumber непустой до 64 знаков; tireBrand/tireModel до 100.
- Vehicle: VIN из 17 заглавных латинских букв/цифр без I/O/Q; brand/model непустые до 100 знаков; productionYear >= 1886; mileageKm обязателен и >= 0; color до 50; указанные ID компонентов > 0.
- Существующая семантика PUT связей сохранена: null у одиночного ID не сбрасывает связь, wheelIds=[] очищает колёса, wheelIds=null оставляет набор.

## Учебные критерии производительности

- Последовательные чтения: p95 <= 100 мс, POST: p95 <= 200 мс; ошибок 0, по 3 повтора 300 запросов.
- Стресс: ступени 1/8/32/64/128 клиентов по 5 секунд; смешанная нагрузка 32 клиента 10 секунд; запись 128 клиентов 8 секунд. Доля ошибок < 1%, p95 <= 2000 мс.
- Восстановление: 200 GET без ошибок; p95 <= 3 * исходный p95 + 50 мс; успешные POST не теряются и не дублируются.
- Это критерии данного локального стенда, не SLA продукта и не оценка production-ёмкости.

## PostgreSQL

- Лабораторные испытания: PostgreSQL 17.11; образ закреплён по digest в compose.lab.yaml и тестах.
- Обычный docker-compose.yml из master использует PostgreSQL 16 Alpine; отдельные нагрузочные
  результаты для этого окружения в отчёте не заявляются.
- Схема и начальные данные используют исходные PostgreSQL V1/V2 из master без изменения
  их содержимого и идентификаторов Liquibase: BIGSERIAL, TIMESTAMP, NUMERIC(4,2)/(4,1).
- Дополнительный V3 после seed выставляет последовательности на MAX(id), чтобы первый
  POST не конфликтовал с уже вставленными идентификаторами. Всего 14 changeset.
- Интеграционные тесты поднимают временный PostgreSQL через Testcontainers;
  бенчмарки и стресс используют отдельный контейнер на каждый запуск.
